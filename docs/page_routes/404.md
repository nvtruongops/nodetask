# 404 Not Found Route Specification (`404.md`)

> **Route Path**: `*` (Catch-all non-matching routes)  
> **Route Type**: `PUBLIC`  
> **Layout Shell**: `PublicLayoutShell`  
> **Specification Version**: `1.4.0`  
> **Status**: `APPROVED`  

---

## Overview
Trang 404 Not Found (`/404`) hiển thị khi người dùng truy cập một tuyến đường không tồn tại trên hệ thống **`nodetask`**. Trang cung cấp thông báo chuẩn Zero-Icon, nút quay về Trang chủ, nút Tìm kiếm nhanh tài liệu cho Guest (`/search`) và nút chuyển sang Workspace cho User đã đăng nhập (`/workspace`).

---

## Route Config
- **URL Path**: `*` / `/404`
- **Access Type**: `PUBLIC`
- **Auth Guard**: None (Công khai cho cả `GUEST` và `USER`)
- **Layout Shell**: `PublicLayoutShell`

---

## Route Dependencies
- **Layout Shell**: `PublicLayoutShell`
- **Global Stores**: `useAuthStore`
- **Providers**: `ThemeProvider`
- **Router**: `ReactRouter`

---

## Non-Functional Requirements & Rendering Strategy
- **Rendering Strategy & HTTP Status Contract**:
  - **SSG / Edge SSR**: Trình chủ máy chủ trả về mã HTTP Status Header `404 Not Found`.
  - **Client-Side SPA**: Server trả về HTML bundle tĩnh, React Router catch-all route render màn hình 404 client-side.
- **CDN Caching Policy**: `Cache-Control: no-store, no-cache, must-revalidate`

Giao diện tuân thủ 100% **Zero-Icon Rule**. Hiển thị CTA linh hoạt theo trạng thái đăng nhập:

```text
    │   ├── [ErrorMessage contentKey="not_found.message"]
    │   ├── [GuestActions gap="16px" visibleIf="!isAuthenticated"]

    │   │   ├── [SearchButton target="/search"] -> contentKey="not_found.cta.search"
    │   │   └── [ContactButton target="/contact"] -> contentKey="not_found.cta.contact"

    │       ├── [WorkspaceButton target="/workspace"] -> contentKey="not_found.cta.workspace"
    │       └── [SearchButton target="/search"] -> contentKey="not_found.cta.search"
    └── [PublicFooter]
```

## Interactions & Event Analytics

### Comprehensive Analytics Event Contract
- `not_found.viewed`: Fired khi render 404 view. Gửi kèm payload metadata:
  - `path`: `window.location.pathname` (đường dẫn lỗi không tồn tại).
  - `referrer`: `document.referrer` (trang nguồn dẫn tới liên kết hỏng).
  - `language`: `navigator.language`.
- `not_found.home_clicked`: Fired khi nhấn `[RETURN TO HOMEPAGE ->]`.
- `not_found.search_clicked`: Fired khi nhấn `[SEARCH DOCUMENTS]`.
- `not_found.workspace_clicked`: Fired khi nhấn `[GO TO WORKSPACE]`.
- `not_found.contact_clicked`: Fired khi nhấn `[REPORT BROKEN LINK]`.

## Acceptance Criteria & Testing Scenarios (Given-When-Then)

```gherkin
Scenario: Guest User Visits Non-Existent Route
  Given an unauthenticated guest user
  When the user visits URL "/invalid-route-path"
  Then the 404 Not Found page is rendered
  And CTA buttons "[RETURN TO HOMEPAGE ->]", "[SEARCH DOCUMENTS]" and "[REPORT BROKEN LINK]" are visible

Scenario: Logged-in User Visits Non-Existent Route
  Given an authenticated user with valid session
  When the user visits URL "/invalid-route-path"
  Then CTA button "[GO TO WORKSPACE]" is visible

Scenario: Focus Management on Page Mount
  Given any user navigating to a 404 route
  When 404 component mounts
  Then keyboard focus is automatically placed on heading element "not-found-heading"

Scenario: Screen Reader Announcement
  Given a screen reader user
  When 404 page loads
  Then screen reader announces "404 // ROUTE NOT FOUND" via aria-live="polite"

Scenario: Analytics Event Firing with Broken Link Metadata
  Given a user clicking a broken link from "/about" to "/missing-page"
  When 404 page renders
  Then analytics event "not_found.viewed" is fired with path="/missing-page" and referrer="/about"

Scenario: Mobile Responsive Layout Alignment
  Given a mobile device viewport width <768px
  When 404 page renders
  Then action buttons stack vertically with full width

Scenario: No-JS Fallback Display
  Given a browser with JavaScript disabled
  When visiting a non-existent URL
  Then noscript warning "NODETASK 404 Page requires JavaScript." is displayed
```
