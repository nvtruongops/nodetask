## 1. Overview & Route ID
- **Route ID**: `ERROR_403` (Dùng cho Analytics, Permission Audit, RBAC Enforcement, Incident Tracking)
- **Route Name**: `error.403`
- **Description**: Trang hiển thị lỗi 403 Forbidden (`/403`). Kích hoạt khi người dùng đã đăng nhập hợp lệ nhưng tài khoản không có đủ quyền RBAC (`USER`, `ORG_MEMBER` cố truy cập trang `/admin` hoặc Workspace thuộc Organization khác mà mình không phải thành viên). Giải thích lý do từ chối truy cập và hỗ trợ nút chuyển về Workspace cá nhân hoặc gửi yêu cầu nâng quyền tới Admin.

## 7. Page State Machine & UI Transitions
- **State Machine Flow**:
  `IDLE` → `REQUESTING_ACCESS` → `REQUEST_SENT` | `NAVIGATING_BACK`
- **UI State Breakdown**:
  - `IDLE`: Hiển thị thông tin tài nguyên bị chặn và vai trò hiện tại của tài khoản.
  - `REQUESTING_ACCESS`: Người dùng bấm nút `[Request Access from Admin]`, gửi yêu cầu RPC.
  - `REQUEST_SENT`: Thông báo yêu cầu đã được gửi thành công `[Access Request Sent]`.
  - `NAVIGATING_BACK`: Nút dẫn người dùng quay về `/workspace` khả dụng của mình.

## 9. Error Mapping & Handling
| Status Code | Trigger Condition | UI Error Content Key | Recovery Action | Logging Tag |
| :--- | :--- | :--- | :--- | :--- |
| `401` | Người dùng bị mất phiên làm việc khi xem 403 | `error.403.session_expired` | Chuyển hướng tới `/auth/login` | `HTTP_403_SESSION_EXPIRED` |
| `403` | Người dùng không đủ quyền trên tài nguyên yêu cầu | `error.403.insufficient_permissions` | Gợi ý chuyển hướng về Workspace cá nhân | `HTTP_403_FORBIDDEN` |
| `500` | Lỗi máy chủ khi xử lý yêu cầu xin cấp quyền | `error.403.server_error` | Thử lại sau | `HTTP_403_SERVER_ERROR` |

## 10. Acceptance Criteria & QA Scenarios

```gherkin
Scenario: USER role attempts to access /admin
  Given an authenticated user with role "USER"
  When navigating directly to "/admin"
  Then the route guard intercepts and redirects to "/403"
  And the page displays ErrorCodeLabel "[HTTP 403: FORBIDDEN]"
  And provides button "[Return to My Workspace]" pointing to "/workspace"

Scenario: ORG_MEMBER requests access to restricted workspace
  Given an ORG_MEMBER on "/403" page after trying to access an Admin-only workspace
  When clicking "[Request Access from Admin]"
  Then the system calls `WorkspaceEndpoint.requestAccess()`
  And displays confirmation message "[Access Request Sent]"
```
